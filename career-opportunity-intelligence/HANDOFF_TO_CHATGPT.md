# Sanitized Phase 2B-1 Handoff

## Architecture

The provider-neutral Python standard-library core normalizes and deduplicates structured jobs, applies source authority, classifies role families, aggregates exact requirements, matches private-runtime evidence references, calculates transparent fit components, exports JSON/CSV/Markdown, and builds inert Firecrawl plans. A fixture adapter accepts synthetic Firecrawl-shaped data; the live adapter always raises `LiveExecutionDisabled`.

## Deliverables

Schemas cover jobs, fits, evidence links, and operation plans. CLI commands cover configuration validation, normalization, deduplication, classification, aggregation, evidence matching, scoring, export, planning, and an ignored synthetic demo. Tests and read-only CI validate deterministic behavior, JSON, compilation, repository safety, and existing claim integrity.

## Limits and next task

There is no semantic/LLM matching, live transport, database, monitor activation, application behavior, or resume generation. Phase 2B-2 must use a supported authenticated Firecrawl client, inventory tools and credits, validate Search/Scrape/Map/bounded Crawl/Batch Scrape, use Interact only if necessary, preserve official sources, and commit no live output. Private candidate evidence, preferences, and approval decisions remain required outside this public repository. Recommended next task: perform the gated live adapter validation using sanitized output only.
